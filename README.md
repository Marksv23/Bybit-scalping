# Bybit-scalping — сканер эффективности скальпинга на Bybit CFD

`scalpscan` ищет инструменты Bybit CFD (TradFi, MetaTrader 5), у которых **прямо сейчас** лучшая математика
для скальпинга на 1m/5m (доп. 15m) при депозите **$30**. Он не прогнозирует направление цены и не говорит BUY/SELL.

Все данные берутся **только из вашего терминала MT5 в реальном времени**: bid/ask, спецификация контракта,
маржа (калькулятор терминала), бары 1m/5m/15m, тиковый поток. Если чего-то нет, отчёт пишет
`LIVE DATA UNAVAILABLE` / `MARGIN UNAVAILABLE` / `n/a`, и значение не подставляется.

## Установка (Windows)

Официальный пакет `MetaTrader5` работает только на Windows и подключается к локальному терминалу.

```bat
git clone <repo> && cd Bybit-scalping
py -m pip install -r requirements.txt
copy config.example.toml config.toml   :: при необходимости поправьте
```

Запустите терминал Bybit MT5 и войдите в CFD-аккаунт. В настройках терминала должна быть включена
алгоритмическая торговля (Tools → Options → Expert Advisors → Allow algorithmic trading); для чтения данных
этого обычно достаточно.

## Команды

Интерактивно: `py -m scalpscan`, затем команды. Разово: `py -m scalpscan SCAN FOREX`.

| Команда | Что делает |
| - | - |
| `SCAN` | полный анализ всех символов (`symbol_group` в config) |
| `SCAN FOREX` / `SCAN INDEX` / `SCAN COMMODITIES` / `SCAN STOCKS` / `SCAN CRYPTO` | только один класс |
| `COMPARE USOUSD.s AUDJPY.s` | сравнение двух инструментов по одинаковым параметрам |
| `WHY XAUUSD.s` | все 21 параметр + разбор score по компонентам и фильтрам |
| `REFRESH` | заново получить данные и пересчитать последнюю команду |

`--save reports` сохраняет каждый отчёт в Markdown. Суффикс можно не писать: `WHY XAUUSD` найдёт `XAUUSD.s`.

## Отчёт SCAN

* `Analysis time` и `Data freshness` (время котировок и загрузки баров/тиков, UTC), брокер, сервер,
  DEMO/REAL, плечо, сдвиг времени сервера, текущая сессия, high-impact события.
* **TOP 10 — RIGHT NOW**: Spread (pts), Spread cost ($ на мин. лоте), 1m/5m movement (средний диапазон
  свечи в цене и в $), Min margin ($ и % депозита), Cost/Movement (1m · 5m), Score.
* Пояснение для TOP-5, **BEST FOR $30** («Наиболее эффективный по заданным критериям прямо сейчас.»).
* Для TOP-3: размер позиции, маржа, стоимость 1 и 10 тиков, break-even, P/L при +0.1% и +0.25% (gross/net).
* **WATCH NOW** (3) с оптимальным таймфреймом и **AVOID NOW** (3) с конкретными причинами.

## Методика (воспроизводимо)

Все расчёты ведутся для **минимального лота** `volume_min`.

| Величина | Формула |
| - | - |
| Стоимость 1 тика | `trade_tick_value_loss × lot` (валюта счёта; для P/L берётся `…_profit`) |
| Spread cost | `(ask − bid) / tick_size × стоимость тика` |
| Round-trip cost | `spread cost + commission × lot × 2` |
| Break-even | `round-trip / стоимость тика` тиков |
| Cost/Movement 1m, 5m | `round-trip в цене / средний (high−low)` последних 30 баров 1m / 24 баров 5m |
| ATR | Wilder ATR(14) по закрытым барам |
| Активность | средний 1m-диапазон за 30 мин / медиана за 4 ч |
| Ликвидность | число тиков (изменений bid/ask) в минуту за последние 5 мин |
| Slippage | данных исполнения нет → прокси: текущий спред / медианный и p90/медиана за 5 мин |
| Маржа | `order_calc_margin` терминала для BUY и SELL, берётся большее |
| Риск | стоимость стопа 1×ATR(5m) на мин. лоте в % депозита |

**Почему голый спред ничего не значит.** `USOUSD.s` 23 pts и `AUDJPY.s` 22 pts — это разные деньги:
стоимость тика зависит от tick size, размера контракта, мин. лота и валюты котирования. Поэтому сравниваются
$ на мин. лоте и доля от типичного движения, а не пункты.

### Scalping Efficiency Score (0–100)

Каждый компонент линейно нормируется в 0..1 (1 = «хорошо», 0 = «плохо»), затем умножается на вес:

| Компонент | 1.0 при | 0.0 при | Вес |
| - | - | - | -: |
| Cost / 5m movement | ≤ 5% | ≥ 40% | 25 |
| Cost / 1m movement | ≤ 15% | ≥ 100% | 15 |
| Маржа, % депозита | ≤ 5% | ≥ 35% | 15 |
| Risk fit: стоп 1×ATR5, % депозита | ≤ риск на сделку (2%) | ≥ 3× риска | 10 |
| Активность (×к 4h-норме) | ≥ 0.9 | ≤ 0.3 | 15 |
| Стабильность спреда | ≤ ×1.1 к медиане | ≥ ×3 | 10 |
| Ликвидность (лог. шкала) | ≥ 120 тиков/мин | ≤ 5 | 10 |

Высокая волатильность **не даёт бонуса**: активность ограничена сверху 1.0, а всплеск > ×2.5 к норме
(новости, гэп) штрафуется. При `⚠ HIGH EVENT RISK` (high-impact событие по валюте инструмента
за 30 мин до / 10 мин после) score умножается на 0.85. Инструмент не удаляется.

### Фильтры (инструмент исключается)

* нет свежей котировки (старше 120 с) → `LIVE DATA UNAVAILABLE`; нет маржи/стоимости тика/истории;
* маржа мин. позиции > 35% депозита (**не подходит**; ≤ 15% **подходит**, ≤ 35% **условно подходит**);
* round-trip > 100% средней 1m свечи или > 50% средней 5m свечи;
* спред расширен более чем ×3 к медиане за 5 мин;
* < 5 тиков/мин;
* стоп 1×ATR(5m) на мин. лоте > 20% депозита.

Все пороги и веса настраиваются в `config.toml`.

## Ограничения и допущения

* **Комиссия**: MT5 API её не отдаёт, она задаётся в `config.toml` (Zero-Fee = 0). Отчёт всегда это показывает.
* **Slippage**: реального исполнения нет, используется прокси по поведению спреда.
* **Ликвидность**: объёмы стакана для CFD недоступны; используется частота тиков.
* **Время**: MT5 отдаёт время сервера брокера; сдвиг к UTC определяется автоматически по самой свежей
  котировке (или задаётся `server_utc_offset_hours`). Часы вашего ПК должны быть синхронизированы.
* **Календарь**: публичный фид ForexFactory (только high impact), кэш 15 мин. Если он недоступен,
  отчёт пишет `CALENDAR UNAVAILABLE — event risk NOT checked`.
* Это аналитический инструмент, а не торговый совет.

## Разработка

```bash
pip install -r requirements-dev.txt
python -m pytest
```

Тесты используют синтетические фикстуры и заглушку модуля `MetaTrader5`. Это не рыночные данные,
они нужны только для проверки формул и отчёта.
